# NotchMeter

Нативний застосунок для macOS, що показує ліміти **Codex** і **Claude Code** та стан агентів у зоні вирізу (notch) MacBook.

Три стани:

1. **У спокої** біля вирізу видно лише крапки активності — і лише поки якийсь агент працює або чекає вашої відповіді. Коли всі мовчать, виріз чистий.
2. **Наведення на виріз** показує індикатори обабіч нього: типово ліворуч Codex (`CX`, синій), праворуч Claude (`CC`, помаранчевий) — шкала найзаповненішого вікна ліміту, відсоток і мітка цього вікна (`5г`, `7д`). Вікно в кожного інструмента обирається окремо, тож Codex може показувати тиждень, а Claude — 5 годин.
3. **Клік** розгортає повну панель: усі вікна лімітів із часом до скидання та список активних сесій із тривалістю ходу. Повторний клік повертає індикатори, а відведення курсора ховає все.

**Індикатор активності** — крапка кольору інструмента: пульсує, поки агент виконує задачу; число поруч показує, скільки сесій працює одночасно; біле кільце навколо крапки означає, що сесія чекає вашої відповіді (`2/1` = двоє працюють, один чекає).

Опитування API Claude обмежене: панель оновлює дані при появі на очах, але не частіше ніж раз на 20 секунд, а у відповідь на HTTP 429 робить паузу, яку просить сервер. Кнопка «Оновити зараз» у налаштуваннях ці обмеження ігнорує.

**Налаштування** — окреме вікно, де детально задається вміст:

- **Монітор:** на якому екрані показувати виріз — автоматично (екран MacBook, а з закритою кришкою — монітор із рядком меню), головний або конкретний монітор. На екрані без вирізу висота дорівнює рядку меню або задається вручну.
- **При наведенні:** хто ліворуч і праворуч від вирізу, яке вікно ліміту показувати, назва агента (коротко, повністю чи без неї), шкала та її колір (за заповненням чи колір агента), відсоток, режим «використано» чи «залишок», мітка вікна (5г, 7д), час до скидання, крапка активності й лічильник сесій. Ширина крил підлаштовується під увімкнене.
- **Панель, ліміти:** які агенти й які вікна лімітів показувати (5 годин, тиждень, Opus, застосунки), назва плану, шкала та її колір, «використано» чи «залишок», формат часу скидання (скільки лишилось, точний час, обидва або нічого), позначка «застаріло», помилки.
- **Панель, сесії:** чи показувати список, сесії в простої, скільки рядків, а в рядку — назва, тека, стан, тривалість ходу, кроки Codex; час останнього оновлення.
- А також частота оновлення лімітів (звичайна: Claude — раз на 2 хв, Codex — раз на 20 с; або удвічі чи вп'ятеро рідше), «Оновити зараз» і автозапуск. Відкривається з меню (**Cmd+,**), яке з'являється по кліку на іконку в рядку меню або по правому кліку на панелі; крім налаштувань, у меню лише «Вийти».

- **Розташування** — який інструмент стоїть ліворуч від вирізу, а який праворуч. Розгорнута панель перелічує їх у тому самому порядку.
- **Ліміт в індикаторі** — автоматично (найзаповненіше вікно, окремо для кожного інструмента), завжди 5 годин або завжди тиждень. Якщо в інструмента обраного вікна немає, показується найзаповненіше, а мітка поруч підказує, яке саме.

## Збірка

Потрібні лише Command Line Tools (Xcode не потрібен).

```bash
make run       # зібрати build/NotchMeter.app і запустити
make install   # скопіювати в /Applications
make dump      # вивести ліміти й сесії в термінал без UI
make icon      # перемалювати Resources/AppIcon.icns
```

Іконка лежить у репозиторії готовою — `make icon` потрібен лише після правок у `Scripts/make-icon.swift`, який малює її на CoreGraphics і збирає `.icns` через `iconutil`.

## Звідки беруться дані

| Що | Джерело |
|---|---|
| Ліміти Codex | останній `token_count` у `~/.codex/sessions/**/rollout-*.jsonl` (без мережі) |
| Ліміти Claude | `GET api.anthropic.com/api/oauth/usage` з OAuth-токеном із Keychain (`Claude Code-credentials`) |
| Сесії Claude | `~/.claude/sessions/<pid>.json`, поле `status` |
| Сесії Codex | `~/.codex/state_5.sqlite` + пара подій `task_started` / `task_complete` у лозі |

Токен Claude застосунок лише читає й ніколи не оновлює сам: інакше він конкурував би з Claude Code за одну OAuth-сесію і ламав йому доступ до Keychain. Коли токен протухає, NotchMeter просить оновити його сам Claude Code: запускає у фоні `claude -p /usage --no-session-persistence --strict-mcp-config`. Це локальна команда, модель вона не викликає й квоту не витрачає, а CLI перед нею штатно оновлює свій токен. Без цього дані застигали б, поки ви працюєте лише в десктопному Claude: той тримає свій токен окремо й цей запис не оновлює. Запуск відбувається не частіше ніж раз на 10 хвилин і не показується як сесія біля вирізу.

Якщо час скидання вікна ліміту вже минув, а свіжих даних ще немає, вікно показується як скинуте (0 %), а не зі старим відсотком.

## Відомі обмеження

- Токен Claude читається через `/usr/bin/security` — так само, як його читає сам Claude Code, тому macOS не питає дозволу ні після перезбірки, ні після оновлення токена. Якщо все ж з'являється вікно «security wants to access…», доступ до запису зламано раніше: введіть пароль і натисніть «Завжди дозволяти» або перелогіньтеся (`claude auth logout && claude auth login`).
- Для оновлення токена потрібен встановлений Claude Code CLI (`~/.local/bin/claude` або Homebrew). Якщо протух і refresh-токен (його строк — кілька тижнів), панель покаже «потрібен вхід» — виконайте `claude auth login` у терміналі.
- opencode поки не підтримується: OpenCode Zen не має API квот. Заготовка — `Providers/OpenCodeProvider.swift`.
